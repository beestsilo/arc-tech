CPU–RAM–bus instruction cycle

Teaching model, not a cycle-accurate simulator: an accumulator machine with 8-bit words and 16 words of RAM (instruction = opcode nibble + address nibble). Values are shown in decimal, with hex marked h; results wrap modulo 256. Real CPUs pipeline, use caches and differ in encoding. Edit the RAM data cells to see how results change.

RAM (address, contents)

Gold outline: PC points here. Shaded: address currently on the address bus. Program cells are fixed; data cells are editable.

    Cache hit / miss simulation

    Simplified model: direct-mapped cache with 4 lines, 16 memory blocks, line = block mod 4, tag = block ÷ 4. Real caches differ (associativity, line size, policies). Start state: all lines empty.

      Virtual machine resource allocation

      Conceptual model with illustrative values: a host with 8 cores and 16 GB of RAM. RAM is reserved per VM (admission control). vCPUs can be overcommitted up to the ratio you choose, and a round-robin scheduler gives vCPUs turns on the cores each tick. It is not a model of any specific hypervisor, and the numbers are not measurements.

      Keyboard matrix scan

      Teaching model: a 4 × 4 key matrix (16 keys). The controller drives one row at a time and reads the four columns. Tap keys to press or release them. Try Q, W and A together with diodes off. Real keyboards differ in size, wiring and firmware.

      Number base converter

      Convert between decimal, binary and hexadecimal. Whole numbers up to 4,294,967,295 (32 bits) are supported. It shows the place-value working for binary input and how the value looks in 8 bits.
